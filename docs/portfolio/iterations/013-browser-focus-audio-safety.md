# 013 · 브라우저 이탈 자동 정지와 오디오 안전성

## 목표

- 다른 창이나 탭으로 이동해도 전투 시간이 계속 흐르지 않게 한다.
- 복귀 순간 이전 효과음이 한꺼번에 재생되거나 배경음악이 중첩되는 문제를 막는다.
- 수동 일시정지와 자동 일시정지를 구분해 플레이어가 재개 시점을 직접 결정하게 한다.
- 장면을 다시 시작해도 브라우저 이벤트 리스너와 음악 인스턴스가 늘어나지 않게 한다.

## 문제

Phaser의 기본 `pauseOnBlur`는 창을 벗어날 때 Sound Manager 전체를 일시정지했다가 포커스가
돌아오면 다시 재개한다. 이 과정에서 짧은 전투 효과음까지 누적되거나, 장면 재시작 뒤 남은
음악과 새 음악의 생명주기가 충돌하면 소리가 갑자기 크게 들릴 가능성이 있었다. 또한 기존
게임 일시정지는 사용자가 멈춤 버튼을 누르는 경우만 다뤄 브라우저 이탈 중 전투가 계속됐다.

## 수정 설계

1. Phaser의 전체 오디오 자동 재개를 끄고 게임이 음악과 효과음을 직접 관리하게 했다.
2. `visibilitychange`, `blur`, `focus`를 하나의 브라우저 활동 상태로 변환했다.
3. 플레이 가능한 단계에서 창을 벗어나면 전투 타이머와 트윈을 자동으로 멈춘다.
4. 복귀만으로 전투나 오디오를 재개하지 않고 `계속하기` 또는 다음 사용자 입력을 기다린다.
5. 창을 벗어나는 즉시 재생 중인 일회성 효과음을 정리하고 새 효과음 요청을 차단한다.
6. 배경음악은 제거 후 재생이 아니라 하나의 인스턴스를 일시정지·재개한다.
7. 사용자가 이미 수동 정지한 상태라면 자동 정지 요청이 그 원인과 안내 문구를 덮어쓰지 않는다.
8. 장면 종료 때 브라우저 활동 구독을 해제해 재시작 후 리스너가 중복되지 않게 했다.
9. 기존 음량·음소거 저장값은 같은 `AudioSettingsService`를 통해 그대로 유지한다.

## 객체 설계

- `PageActivityMonitor`: 브라우저 활동 상태를 제공하는 포트
- `BrowserPageActivityMonitor`: DOM 이벤트를 활동 상태로 바꾸는 어댑터
- `PageActivityCoordinator`: 활동 상태와 게임 동작을 연결하고 구독 수명을 관리하는 응용 객체
- `GamePauseState`: 수동·자동 일시정지 원인을 보존하는 순수 상태 객체
- `BattlefieldAudioDirector`: 창 이탈 중 음악 정지, 효과음 정리와 재생 차단
- `SingleTrackMusicController`: 단일 음악 인스턴스 재사용과 pause/resume 담당
- `PauseMenu`: 자동 정지 원인에 맞는 복귀 안내 표현

브라우저 API, 게임 흐름, Phaser 오디오 제어를 각각 포트·응용 정책·어댑터로 분리해 외부 이벤트를
실제 브라우저 없이도 테스트할 수 있게 했다.

- 수동 정지가 자동 정지에 의해 덮어써지지 않는 상태 테스트 추가

- 로컬 브라우저 콘솔 경고·오류 0건

## 트러블슈팅

- Phaser 게임 설정의 `AudioConfig`에는 `pauseOnBlur` 항목이 없었다. 게임 생성 뒤
  `BaseSoundManager.pauseOnBlur`를 끄는 방식으로 타입과 실제 동작 위치를 일치시켰다.
- 탭 복귀 때 Sound Manager 전체를 `resumeAll` 하면 중간에 멈춘 효과음도 재개될 수 있다.
  배경음악 핸들만 재개하고 일회성 효과음은 이탈 시 완전히 정리하도록 범위를 제한했다.
- 장면 재시작은 같은 Scene 인스턴스를 다시 사용한다. 종료 이벤트에서 활동 감지 구독을
  명시적으로 해제하고 새 `create` 시작 시 남은 구독도 한 번 더 정리하도록 했다.

## 포트폴리오 포인트

사용자 피드백으로 발견한 브라우저 복귀 오디오 문제를 단순 볼륨 조정이 아니라 브라우저 상태,
게임 일시정지, 오디오 인스턴스 생명주기의 충돌로 분석했다. 포트·어댑터와 순수 상태 객체를
도입하고 재현 가능한 자동 테스트로 회귀를 막아 웹게임 서비스 환경의 안정성을 높였다.
