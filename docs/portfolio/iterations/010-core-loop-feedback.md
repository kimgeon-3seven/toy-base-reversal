# 010 · 핵심 루프 전달력과 전투 피드백

## 목표

- `방어 성과 → 공격 자원 → 같은 방어선 공략`의 인과관계를 별도 설명 없이
  플레이 화면에서 이해하게 한다.
- 일반 공격 이펙트를 더 늘리지 않고 전략적으로 중요한 전환점만 강조한다.

## 문제

기존 결과 화면은 처치·누수·코어와 출격 포인트를 모두 표시했지만 서로 다른
문장으로 나열되어 있었다. 플레이어가 좋은 방어가 왜 강한 공격 부대로 이어지는지,
공격 라운드의 대상이 정말 같은 설계인지 직접 해석해야 했다. 공격 전투도 모든
타격 피드백은 있었지만 집중 공격 성공과 코어 붕괴 단계가 별도로 구분되지 않았다.

## 수정 설계

1. `CoreLoopFeedbackPresenter`가 도메인 결과를 처치율·코어 보존율 막대,
   출격 포인트 연결 문장, 복원된 방어선 요약과 라운드 비교 정보로 변환한다.
2. 결과 오버레이에 재사용 가능한 진행 막대 모델을 추가하고 방어 결과와 공격
   결과가 같은 시각 언어를 공유하게 했다.
3. 역할 반전 제목을 `내 방어선 → 내 공략 대상`으로 바꾸고 설계를 최대 체력으로
   복원한다는 사실을 명시했다.
4. 공격 준비 임무 카드에 같은 설계의 타워·장애물 구성, 현재 해금된 상성 유닛,
   방어 보상 산식을 표시했다.
5. `AttackCombatFeedbackPolicy`가 적 코어 50%·25% 경계와 집중 공격 대상
   파괴만 전략 콜아웃으로 선택한다.
6. 공격 성공 화면에서 방어 등급·처치율·코어 보존율과 공략 시간·출격 포인트를
   비교해 양쪽 역할의 성공을 한 문장으로 마무리한다.

## 트러블슈팅

- 첫 브라우저 QA에서 역할 반전 엠블럼이 진행 막대 라벨과 겹쳤다. 진행 막대가
  있는 전환 화면에서 엠블럼을 좌상단으로 축소 재배치했다.
- 공격 결과의 비교 정보와 다음 해금이 세 줄이 되면서 제목과 겹쳤다. 핵심 비교
  두 줄만 수치 영역에 남기고 다음 해금을 조언 영역으로 옮긴 뒤 전용 간격과
  글꼴 크기를 적용했다.

## QA

- 전체 55개 테스트 파일의 178개 테스트 통과
- ESLint, TypeScript, GitHub Pages·itch.io 프로덕션 빌드 통과
- 로컬 브라우저에서 방어 결과, 역할 반전, 공격 준비와 공격 성공 결과의
  1280×720 배치를 확인하고 콘솔 경고·오류 0건 확인

## 포트폴리오 포인트

게임 규칙을 바꾸지 않고 도메인 결과를 플레이어가 이해할 수 있는 인과관계로
번역했다. 표시 문구를 장면 안에 직접 조립하지 않고 표현 전용 객체로 분리했으며,
전투 알림 역시 임계점 정책으로 제한해 화면 가독성과 확장성을 함께 유지했다.
