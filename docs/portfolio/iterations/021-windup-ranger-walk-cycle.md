# 021 · 태엽 군단·고무줄 사수 보행 루프 안정화

## 목표

- 사용자 QA에서 승인된 방패병 보행은 그대로 유지한다.
- 태엽 군단과 고무줄 사수의 걷기 루프가 끝날 때 자세가 튀는 현상을 줄인다.
- 공격 모션과 전투 밸런스에는 영향을 주지 않는다.

## 문제

이전 개선에서 유닛의 실제 이동 속도와 애니메이션 재생 속도를 연결했지만,
태엽 군단과 고무줄 사수의 원본 보행 시트는 `0 → 1 → 2 → 3 → 0`
순환의 마지막 경계에서 몸과 발의 자세가 크게 바뀌었다. 따라서 프레임 속도가
적절해져도 루프가 반복될 때 순간이동처럼 보였다.

## 판단

문제는 캐릭터 디자인이나 기준선이 아니라 원본 프레임의 순환 순서에 있었다.
새 그림을 생성하면 이미 확정된 외형이 달라질 위험이 있으므로, 검증된 원본을
보존하고 보행 프레임만 결정론적으로 재구성했다.

## 구현

1. 기존 `v1` 보행 시트는 비교 가능한 베이스라인으로 보존했다.
2. 태엽 군단과 고무줄 사수의 각 8방향을
   `접지 → 통과 → 반대 접지 → 통과` 순서로 재구성했다.
3. 결과물을 각각 `unit-windup-walk-8way-v2.png`,
   `unit-ranger-walk-8way-v2.png`로 추가했다.
4. 안정화 스크립트에 `-UniformCycle` 옵션을 추가해 같은 변환을 재현할 수
   있도록 했다.
5. 게임 자산 연결은 두 유닛의 보행 시트만 `v2`로 변경했다. 방패병 보행과
   태엽 군단·고무줄 사수의 공격 시트는 그대로 유지했다.

## 구조

자산 생성은 `stabilize-walk-sprite-sheet.ps1`, 자산 경로 선택은
`GameAssets`, 방향별 프레임 규칙은 `DirectionalAnimationCatalog`가 각각
담당한다. 자산 제작·로딩·재생 정책을 분리해 이후 특정 유닛만 다시 다듬어도
다른 유닛이나 전투 로직에 영향을 주지 않는다.

## QA

- 새 시트 2종이 각각 `640×1280`, 32프레임인지 확인
- 총 64프레임의 불투명 픽셀 하단이 모두 셀 내부 `y=151`인지 확인
- 네 번째 프레임이 두 번째 통과 자세로 돌아와 다음 첫 프레임과 자연스럽게
  연결되는지 픽셀 및 시트 단위로 확인
- 방패병 보행 `v2`와 두 유닛의 공격 `v1` 연결을 회귀 테스트로 보호
- ESLint와 TypeScript 통과
- 전체 73개 테스트 파일, 236개 테스트 통과
- GitHub Pages와 itch.io 프로덕션 빌드 통과
- 로컬 브라우저의 2라운드 플레이어 공격에서 태엽 군단 이동·공격 확인
- 3라운드 방어에서 NPC 고무줄 사수 이동 확인
- 플레이어와 NPC 고무줄 사수는 동일 자산과 애니메이션 프로필을 사용하며,
  공통 경로를 자동 테스트로 확인
- 브라우저 콘솔 오류 0건

## 포트폴리오 포인트

사용자 피드백을 통해 보행 속도와 프레임 연속성을 별개의 문제로 분리했다.
이미 승인된 방패병을 재작업하지 않고, 문제가 남은 두 유닛만 버전 자산으로
교체했으며 원본·변환 스크립트·회귀 테스트를 함께 남겼다. 시각적 개선도
재현 가능한 제작 파이프라인과 변경 범위 통제로 관리한 사례다.
