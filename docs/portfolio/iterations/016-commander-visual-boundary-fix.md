# 016 · 지휘관 전장 경계 이탈 수정

## 목표

- 지휘관이 외곽 그리드로 이동해도 캐릭터 본체와 강조 링이 전장 밖으로 나오지 않게 한다.
- 기존 지휘관 좌표, 타워 표적 우선순위와 공격 밸런스는 바꾸지 않는다.
- 서로 다른 전장 크기나 스프라이트 크기에도 재사용할 수 있는 경계 규칙을 만든다.

## 문제

논리 좌표는 `GridMap.contains`로 이미 검증되어 음수 좌표나 맵 크기 이상의 셀로 이동할 수
없었다. 그러나 외곽 셀의 중심과 전장 테두리 사이 거리는 24px인 반면 지휘관 스프라이트는
76px라서, 외곽 셀에 서면 이미지가 테두리 밖으로 약 14px 돌출됐다. 중앙 진입로도 0열에서
시작하므로 공격 라운드 시작 직후부터 이 문제가 보일 수 있었다.

## 수정 설계

1. 지휘관의 논리 위치와 전투 판정은 기존 그리드 좌표를 그대로 사용한다.
2. `SpriteVisualBoundary`가 전장 사각형과 스프라이트 표시 크기를 기준으로 화면 중심점을 제한한다.
3. 내부 셀의 화면 위치는 변경하지 않고, 외곽에서 이미지가 돌출되는 만큼만 중심을 안쪽으로 보정한다.
4. 지휘관 본체, 장난감 받침, 그림자와 이름표가 같은 보정 좌표를 공유하게 한다.
5. 상단·하단·좌측·우측 모서리와 정상 내부 위치를 순수 단위 테스트로 검증한다.

## 객체 설계

- `SpriteVisualBoundary`: 화면 사각형과 표시 크기만 다루는 순수 표현 정책
- `BattlefieldSpriteRenderer`: 그리드 좌표를 화면 좌표로 바꾼 뒤 지휘관에만 경계 정책 적용
- `AttackCombat`: 기존 이동 가능 셀과 전투 판정을 그대로 유지

표현 문제를 도메인 이동 규칙으로 해결하지 않아 타워 AI와 전투 밸런스가 렌더링 크기에 의존하지
않게 했다.

## QA

- 최초 이동 경계 변경안에서 기존 전투 테스트 6개가 실패하는 것을 확인
- 실패 원인이 지휘관 시작 위치 변경으로 인한 타워 표적·공격 타이밍 변화임을 진단
- 표현 계층 경계 방식으로 교체 후 전체 67개 테스트 파일의 210개 테스트 통과
- ESLint, TypeScript, GitHub Pages·itch.io 프로덕션 빌드 통과
- 로컬 브라우저에서 1라운드 방어·공격을 진행하며 시작점, 상단, 하단, 우하단 경계 확인
- 지휘관 본체와 강조 링이 전장 테두리 안에 유지되고 공격 결과까지 정상 진행
- 브라우저 콘솔 경고·오류 0건

## 트러블슈팅

- 처음에는 외곽 한 셀을 이동 불가로 만들고 시작점을 내부로 옮겼다. 이 변경은 지휘관이 타워에
  한 칸 더 가까워져 기존 전투 테스트 6개와 실제 밸런스에 영향을 줬다.
- 문제의 원인이 좌표 이탈이 아니라 큰 스프라이트의 시각 돌출임을 다시 분리했다. 도메인 변경을
  되돌리고 화면 좌표만 제한해 기존 전투 결과를 모두 복원했다.

## 포트폴리오 포인트

사용자 QA에서 발견한 경계 문제를 좌표 검증, 스프라이트 크기와 전투 회귀로 나눠 진단했다.
첫 해결안이 자동 테스트에서 밸런스를 바꾸는 것을 발견한 뒤 표현 계층의 순수 정책으로 수정해,
시각 오류만 제거하면서 기존 게임 규칙을 보존했다.
