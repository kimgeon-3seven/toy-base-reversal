# 014 · 결과 이해와 빠른 재도전 경험

## 목표

- 별도 설명 없이도 결과와 다음 행동을 즉시 이해하게 한다.
- 키보드를 모르는 플레이어도 마우스만으로 결과 이후 흐름을 완료하게 한다.
- 실패 원인을 구체적으로 알려 재도전이 학습으로 이어지게 한다.
- 웹게임에 맞게 결과 확인부터 새 게임 시작까지의 클릭 수를 줄인다.
- 해커톤 시연과 포트폴리오 공유에 사용할 수 있는 결과 복사 기능을 제공한다.

## 문제

기존 결과 화면은 `Enter`, `R` 단축키가 포함된 텍스트를 클릭 대상으로 사용했다. 클릭은
가능했지만 버튼 형태가 아니어서 행동 우선순위가 약했고, 공격 실패는 서로 다른 원인을 하나의
`공격 실패` 제목으로 묶었다. 새 도전도 장면 재시작 뒤 시작 안내를 한 번 더 거쳐야 했으며,
기록을 다른 사람에게 전달할 방법이 없었다.

## 수정 설계

1. 결과 화면의 주요 행동을 공통 `TextButton` 컴포넌트로 교체했다.
2. 성공 화면은 다음 단계, 실패 화면은 재도전을 가장 큰 기본 행동으로 배치했다.
3. 실패 화면에 `시작 화면으로`를 별도 제공해 재도전과 게임 종료 의도를 분리했다.
4. 새 게임 바로 시작은 장면 데이터로 의도를 전달해 시작 안내 없이 1라운드 준비로 진입한다.
5. 지휘관 사망, 일반 부대 전멸, 제한시간 초과를 서로 다른 제목·원인·개선점으로 표시한다.
6. 일반 모드 완료 기록은 이전 최고 기록과 초 단위로 비교한다.
7. 챌린지는 라운드를 우선하고 같은 라운드일 때 돌파시간을 비교한다.
8. 결과 복사는 게임명, 결과, 핵심 지표와 현재 배포 주소만 간결하게 생성한다.
9. 클립보드 권한이 없거나 거부돼도 게임 흐름은 유지하며 버튼에서 성공·실패를 바로 알린다.
10. 기존 `Enter`, `R` 단축키를 유지해 숙련 플레이어의 흐름은 바꾸지 않았다.

## 객체 설계

- `ResultExperiencePresenter`: 실패 원인과 개인 기록 비교를 만드는 순수 프레젠테이션 객체
- `ResultShareService`: 공유 문구 구성과 클립보드 실패 처리
- `ClipboardWriter`: 외부 클립보드 기술을 감추는 포트
- `BrowserClipboardWriter`: 브라우저 Clipboard API 어댑터
- `RoundResultOverlay`: 결과 표현과 버튼 배치만 담당
- `BattlefieldSceneData`: 일반 재시작과 시작 안내를 건너뛴 빠른 재도전 의도 전달

결과 규칙, 브라우저 API, Phaser UI를 분리해 기록 비교와 복사 실패를 브라우저 없이 테스트할
수 있게 했다.

## QA

- 실패 원인 3종, 일반·챌린지 기록 비교 단위 테스트 추가
- 결과 복사 성공·실패 및 브라우저 어댑터 테스트 추가
- 전체 65개 테스트 파일의 204개 테스트 통과
- ESLint, TypeScript, GitHub Pages·itch.io 프로덕션 빌드 통과
- 로컬 브라우저에서 로딩 → 시작 → 방어 전투 → 방어 결과 흐름 확인
- 방어 결과의 제목·수치·보상·조언·기본 행동·결과 복사 버튼이 겹치지 않는지 시각 확인
- 브라우저 콘솔 경고·오류 0건

## 트러블슈팅

- 최초 복사 피드백은 결과창 뒤의 공통 상태 문구에 표시되어 플레이어가 볼 수 없었다.
  복사 버튼 자체를 `복사 완료 ✓` 또는 `복사할 수 없음`으로 바꾸도록 수정했다.
- 기존 `secondaryAction`은 실제 행동과 설명 문구를 함께 표현했다. 콜백이 있는 항목만 버튼으로
  표시하고 자동 진행 설명은 본문으로 옮겨 가짜 버튼이 나타나지 않게 했다.
- 성공 화면은 두 번째 행동이 없어서 결과 복사 버튼이 한쪽으로 치우쳤다. 보조 행동 유무에 따라
  복사 버튼을 중앙 또는 우측으로 자동 배치했다.

## 포트폴리오 포인트

결과 화면을 단순한 점수 출력이 아니라 다음 플레이를 결정하는 웹게임의 핵심 전환점으로
재설계했다. 사용자 입력 방식, 실패 학습, 기록 비교, 공유와 빠른 재시작을 하나의 흐름으로
연결하면서도 게임 규칙과 기존 단축키는 유지했다.
