# 020 · 공격 유닛 보행 주기 개선

## 목표

- 방패병·태엽 군단·고무줄 사수의 보행 프레임을 실제 이동 속도와 맞춘다.
- 정지·이동·공격 상태가 전환될 때 불필요한 흔들림이나 발 미끄러짐을 줄인다.
- 동일한 규칙을 NPC 방어 웨이브와 플레이어 공격 부대에 함께 적용한다.

## 문제

세 유닛은 이동 속도가 서로 다른데도 모든 걷기 애니메이션을 10fps로
재생했다. 이동 속도가 느린 방패병은 발만 지나치게 빠르게 움직였고, 빠른
태엽 군단과 중간 속도의 고무줄 사수도 실제 전진 거리와 발걸음이 정확히
맞지 않았다. 스프라이트 시트가 있는 유닛에는 사인파 흔들림을 적용하지
않았지만, 공통 재생 속도가 캐릭터의 무게감 차이를 없애고 있었다.

## 진단

- 세 걷기 시트는 모두 `160×160` 셀 32개로 구성되어 있다.
- 총 96개 프레임의 불투명 픽셀 하단이 모두 셀의 `y=151`에 있어 발
  기준선은 이미 고정되어 있었다.
- 렌더러는 도메인의 실제 `isMoving` 상태를 전달하고 있었고, 공격 시
  이동도 취소하고 있었다.
- 따라서 이미지를 다시 생성하거나 캐릭터 위치를 흔드는 대신, 표현 계층의
  보행 주기를 이동 속도에 맞추는 것이 적절했다.

## 구현

1. `WalkAnimationCadence`가 초당 그리드 이동량을 Phaser 애니메이션
   배속으로 변환한다.
2. 기준 애니메이션은 8fps이며, 그리드 한 칸마다 5프레임이 진행되도록
   계산한다.
3. 가독성을 위해 결과 프레임 속도는 4~11fps로 제한한다.
4. 방패병은 약 5.75fps, 고무줄 사수는 약 7.5fps, 태엽 군단은 약
   10.25fps로 재생되어 각 유닛의 무게감과 이동 속도를 구분한다.
5. NPC와 플레이어 렌더러가 모두 각 도메인 유닛의 실제 이동 속도를
   `BattlefieldSpriteView`에 전달한다.
6. 공격과 대기 애니메이션으로 전환할 때 보행 배속을 1로 복원해 다른
   동작의 재생 속도가 오염되지 않게 한다.

## 구조

이동 속도를 계산하는 정책은 `WalkAnimationCadence`, 방향과 프레임 등록은
`DirectionalAnimationCatalog`, 현재 상태에 따른 재생은
`BattlefieldSpriteView`가 각각 담당한다. 밸런스의 이동 속도가 바뀌어도
스프라이트 시트나 렌더러 분기문을 수정할 필요가 없다.

## 포트폴리오 포인트

겉으로 보이는 어색함을 단순히 스프라이트 품질 문제로 판단하지 않고, 96개
프레임의 기준선과 도메인 이동 상태를 먼저 검증했다. 그 결과 자산을 다시
제작하지 않고 실제 이동 속도와 표현 속도를 연결하는 작은 정책 객체로 문제를
해결했으며, 서로 다른 세 유닛과 양 진영에 같은 규칙을 재사용했다.
