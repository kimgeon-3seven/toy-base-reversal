# 004 · 양 진영 방패병 전투 애니메이션 수정

## 발견된 문제

- 공격 라운드에서 방패병이 목표 앞에 멈춘 뒤 공격 자세를 재생하지 않는
  경우가 있었다.
- 방어 라운드의 NPC 방패병은 8방향 시트가 아니라 정적 이미지로 남아
  있었다.
- 걷기 시트 위에 기존 이동 바운스가 중복되고, 이동이 끝난 뒤에도 140ms
  동안 걷기 상태가 유지되어 발 미끄러짐처럼 보였다.

## 원인

1. `CombatEvent`가 공격 주체의 좌표만 전달했다. 같은 칸 주변에 여러 유닛이
   모이면 표현 계층이 가장 가까운 다른 스프라이트를 선택할 수 있었다.
2. `DirectionalAnimationCatalog`의 방패 프로필이 공격 유닛 경로에만 연결돼
   있었다.
3. 표현 계층이 실제 도메인 이동 상태가 아니라 프레임 사이 좌표 차이로
   걷기를 추정했다.
4. 생성 원본 프레임의 자세와 중심점 차이를 공통 사각형만으로 처리해 실제
   캐릭터 피벗이 완전히 고정되지 않았다.

## 수정

1. 모든 공격 이벤트에 `sourceId`를 추가하고 타워·NPC·공격 유닛·지휘관을
   ID로 직접 찾도록 변경했다. 같은 공격 애니메이션도 이벤트마다 처음부터
   다시 재생한다.
2. 방패 프로필을 진영과 무관한 `tank` 아키타입 프로필로 변경해 NPC와
   플레이어 방패병이 동일한 걷기·공격 시트를 사용한다. 진영은 붉은색 또는
   청록색 장난감 받침으로 구분한다.
3. `AttackUnit`과 `DefenseEnemy`가 `isMoving`을 제공하고 표현 계층이 이 값을
   사용하도록 했다. 그리드 경계의 한 프레임 공백만 연결하도록 정지 유예를
   48ms로 줄였다.
4. 시트 애니메이션이 있는 캐릭터에는 별도의 사인파 이동 바운스를 적용하지
   않는다.
5. 걷기 루프를 `contact → passing → opposite contact → passing` 순서로
   재구성하고 각 프레임을 동일 배율, 수평 중심, 발 기준선에 맞춘
   `unit-shield-walk-8way-v2.png`로 버전업했다.

## 이미지 생성 실험과 판단

Built-in ImageGen 편집 모드에 기존 8방향 시트와 `unit-shield-v2.png`를
참조로 제공했다. 프롬프트의 핵심 요구는 정확한 8행×4열, 방향 순서
`N, NE, E, SE, S, SW, W, NW`, 동일한 카메라·배율·발 기준선, 네 단계 보행,
투명 배경이었다.

생성 결과는 프레임 중심은 개선됐지만 일부 방향이 중복되고 남서 방향에서
방패가 두 개가 되는 장비 오류가 남았다. 교정 편집 후에도 방향 정확성이
충분하지 않아 생성 결과를 게임 에셋으로 채택하지 않았다. 검증된 기존
방향 프레임을 결정론적 스크립트로 재배열·정렬하는 방식을 최종 선택했다.
