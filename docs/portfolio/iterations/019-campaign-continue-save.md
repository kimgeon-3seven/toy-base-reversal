# 019 · 일반 모드 캠페인 중간 이어하기

## 목표

- 최고 도달 라운드 표시를 실제 플레이 가능한 이어하기로 확장한다.
- 플레이어가 브라우저를 닫아도 자신이 만든 방어선과 자원 운용의 맥락을 잃지 않게 한다.
- 전투 시뮬레이션 전체를 직렬화하지 않고 안정적인 준비 단계 체크포인트로 복귀한다.

## 문제

기존 로컬 기록은 일반 모드에서 가장 높게 완료한 라운드만 남겼다. 게임을
다시 실행하면 방어 설계, 강화 단계와 남은 건설 부품이 모두 초기화되어 실제로
게임을 이어갈 수 없었다. 화면 안의 `S` 저장도 전투 전 설계를 복구하는 메모리
기능이라 브라우저 종료를 견디지 못했다.

## 설계

영구 기록과 진행 중 캠페인을 서로 다른 저장 객체로 분리했다.

- `CampaignCheckpointRepository`: 저장 매체를 추상화하는 포트
- `LocalStorageCampaignCheckpointRepository`: 브라우저 저장 어댑터
- `CampaignSaveService`: 체크포인트 생성·복원·삭제 정책
- `CampaignCheckpoint`: 라운드, 설계, 자원과 단계의 일관성을 검증하는 도메인 객체
- `RoundSession`, `DefenseBlueprint`, `SquadPlan`: 각 객체가 자신의 스냅샷 생성과 복원을 책임짐

저장 데이터에는 현재 일반 라운드, 완료 결과, 누적 공격시간, 타워·장애물의
위치와 강화 단계, 건설 부품, 방어 성과와 공격 편성을 포함한다. 구조물 복원 뒤
다음 생성 번호를 다시 계산해 기존 ID를 덮어쓰는 오류도 방지했다.

## 체크포인트 정책

1. 방어 준비 편집이 성공할 때마다 최신 설계와 부품을 저장한다.
2. 방어 시작 직전에 전투 전 설계를 확정한다.
3. 방어 성공 시 보상과 추천 공격 편성을 저장한다.
4. 공격 편성 변경과 공격 시작 직전에 최신 편성을 저장한다.
5. 공격 성공 시 결과 화면을 닫기 전부터 다음 라운드와 건설 보상 4를 선저장한다.
6. 일반 모드 공격 실패 또는 5라운드 완료 시 진행 저장만 삭제한다.

방어 전투의 적·시설 체력과 공격 전투의 유닛 위치는 저장하지 않는다. 중단 시
각 전투의 준비 단계부터 재개해 도메인 상태를 단순하고 검증 가능하게 유지한다.

## UX

- 저장이 있으면 시작 화면의 기본 행동을 `이어하기`로 변경한다.
- 저장 라운드, 건설 부품과 누적 공격시간을 시작 카드에서 확인할 수 있다.
- `새 게임`은 3초 안에 두 번 눌러야 기존 진행을 삭제한다.
- 일시정지의 `게임 나가기`는 일반 모드 체크포인트가 유지된다고 안내한다.
- 챌린지는 순위 경쟁의 단일 도전 성격을 유지하기 위해 자동 저장에서 제외한다.

## QA

- 라운드 세션의 완료 결과·대기 중 방어 결과·누적시간 왕복 복원 테스트
- 방어 설계의 위치·강화·부품과 구조물 ID 재계산 테스트
- 공격 편성의 진입로 순서·예산·생성 간격 복원 테스트
- 손상 데이터, 잘못된 버전, 완료 캠페인 저장 거부 테스트
- 전체 71개 테스트 파일, 230개 테스트 통과
- ESLint, TypeScript와 Vite 프로덕션 빌드 통과
- 로컬 브라우저에서 새 캠페인 시작, 새로고침, 이어하기 카드와 방어 준비 복원 확인
- 브라우저 콘솔 오류 없음 확인
