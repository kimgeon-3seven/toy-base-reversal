# 015 · 절제된 UI 버튼 오디오 피드백

## 목표

- 마우스로 버튼을 눌렀을 때 입력이 전달됐음을 즉시 알린다.
- 모든 버튼에 큰 소리를 반복하지 않고 행동 중요도에 맞는 소리만 사용한다.
- 기존 전투 시작 확정음과 오류음이 새 버튼음과 겹치지 않게 한다.
- 장면 재시작과 빠른 연타에도 오디오 이벤트가 중복되지 않게 한다.

## 문제

전장 바닥 클릭은 공통 클릭음을 재생했지만 `TextButton`과 지휘관 스킬 카드는 포인터 이벤트
전파를 막기 때문에 소리가 나지 않았다. 이로 인해 같은 마우스 입력이라도 버튼 종류에 따라
피드백이 달랐으며, 모든 콜백에서 직접 효과음을 호출하면 UI와 오디오가 강하게 결합되고 기존
확정음·오류음과 중복될 위험이 있었다.

## 수정 설계

1. 공통 버튼 피드백을 `click`, `confirm`, `silent` 세 종류로 분류했다.
2. 일반 선택·편집·설정 버튼에는 짧은 클릭음을 기본 적용했다.
3. 튜토리얼 시작, 결과 화면 행동, 게임 나가기 확인에는 확정음을 적용했다.
4. 방어·공격 시작은 기존 전투 시작 로직이 확정음을 내므로 버튼 자체는 무음 처리했다.
5. 지휘관 스킬은 정상적인 대상 선택 진입·취소에만 클릭음을 내고 재사용 대기 중에는 기존
   오류음만 들리게 했다.
6. 전역 버튼음을 70ms 간격으로 제한해 연타 시 과도한 소리가 겹치지 않게 했다.
7. 오디오 설정 슬라이더 이동과 마우스 호버에는 소리를 추가하지 않았다.
8. 장면 종료 시 버튼 오디오 구독을 해제해 재시작 후 중복 재생을 막았다.

## 객체 설계

- `UiButtonFeedbackEvent`: UI가 오디오 구현을 몰라도 의도를 발행하게 하는 공통 이벤트
- `PhaserUiButtonFeedbackSource`: Phaser 장면 이벤트를 구독 소스로 변환하는 어댑터
- `UiButtonAudioFeedback`: 클릭 간격 제한과 사운드 플레이어 호출을 담당하는 프레젠테이션 객체
- `UiButtonSoundPlayer`: 실제 오디오 디렉터와 버튼 정책 사이의 작은 인터페이스
- `TextButton`: 기본 클릭 피드백과 버튼별 음색 정책만 선언

버튼, 이벤트 전달, 재생 정책, 실제 Phaser 오디오를 분리해 UI 컴포넌트가 구체 오디오 자산이나
`BattlefieldAudioDirector`에 직접 의존하지 않도록 했다.

## 트러블슈팅

- 전장 입력의 공통 클릭음은 `stopPropagation()`을 사용하는 UI 버튼까지 도달하지 않았다.
  버튼 전용 이벤트를 발행해 전장 조작과 UI 조작의 피드백 경로를 분리했다.
- 전투 시작 버튼에서 새 클릭음과 기존 확정음이 연달아 날 수 있었다. 실제 행동 완료를 알리는
  기존 확정음을 유지하고 해당 버튼 정책만 `silent`로 지정했다.
- 재사용 대기 중 스킬 카드가 클릭음과 오류음을 동시에 낼 수 있었다. 스킬 대상 선택 함수가
  성공 여부를 반환하게 해 정상 동작에만 클릭 이벤트를 발행했다.
- 게임 타이머 기반 제한은 일시정지 중 시간이 흐르지 않아 재개 버튼음까지 막을 수 있었다.
  버튼음 제한에는 게임 시간과 독립적인 실시간 시계를 사용했다.

## 포트폴리오 포인트

단순히 모든 버튼에 효과음을 붙이는 대신 행동의 중요도, 기존 오디오 경로, 연타와 장면 생명주기를
함께 분석했다. 작은 인터페이스와 이벤트 어댑터를 통해 UI와 오디오를 느슨하게 결합하면서 웹게임의
즉각적인 조작 피드백을 높였다.
