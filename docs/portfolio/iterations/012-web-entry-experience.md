# 012 · 웹게임 로딩과 클릭 시작 경험

## 목표

- 첫 접속의 빈 화면을 실제 웹게임다운 로딩 경험으로 바꾼다.
- 이미지·음원 준비 상태와 시작 가능 시점을 플레이어가 명확히 이해하게 한다.
- 첫 입력에서 오디오 권한과 전체화면 선택을 안전하게 처리한다.
- PC 중심 조작을 권장하면서도 작은 화면의 접근을 막지 않는다.

## 문제

기존 `BootScene`은 에셋을 모두 불러온 뒤 곧바로 전투 장면을 시작했다. 느린 네트워크에서는
진행 상태를 알 수 없는 빈 캔버스가 보일 수 있었고, 브라우저 자동 재생 정책 때문에 음악은
게임에 들어간 뒤 다시 입력해야 시작됐다. 전체화면 진입점과 기기 권장 안내도 없었다.

## 수정 설계

1. HTML에 게임 엔진보다 먼저 그려지는 진입 화면을 두어 최초 빈 화면을 제거했다.
2. `BootScene`은 Phaser 로더의 실제 진행률과 파일 오류만 `WebEntryCoordinator`에 전달한다.
3. `DomWebEntryView`는 로딩, 준비 완료, 시작 중, 실패, 게임 상태를 DOM으로 표현한다.
4. 로딩 완료 후 `클릭해서 시작`을 기다리고 그 입력에서 Web Audio 컨텍스트를 재개한다.
5. `전체화면으로 플레이`는 전체화면 요청과 오디오 활성화를 같은 클릭에서 동시에 시작한다.
6. 전체화면 API가 없거나 임베드 정책에 막혀도 일반 플레이는 계속 시작한다.
7. 게임 중에도 우측 상단 버튼으로 전체화면을 전환할 수 있다.
8. `WebEntryDeviceAdvisor`는 화면 크기와 포인터 종류를 바탕으로 PC 권장 문구만 바꾸며
   모바일·좁은 화면을 차단하지 않는다.
9. 로딩 실패 시 네트워크 확인 문구와 장면 재시도 동작을 제공한다.

## 객체 설계

- `WebEntryCoordinator`: 진입 상태와 중복 시작 방지
- `WebEntryFlow`: Phaser 부트 계층이 의존하는 진입 흐름 인터페이스
- `WebEntryView`: 표현 계층 인터페이스
- `FullscreenGateway`: 브라우저 전체화면 기능 인터페이스
- `DomWebEntryView`: DOM 표현 구현
- `BrowserFullscreenGateway`: Fullscreen API 어댑터
- `WebEntryDeviceAdvisor`: PC 권장 여부를 판단하는 순수 정책
- `BootScene`: 에셋 로딩과 Phaser 오디오 활성화만 담당

이 분리로 DOM, 브라우저 API, Phaser 로더를 서로 직접 의존시키지 않고 각 책임을 독립적으로
테스트할 수 있게 했다.

## QA

- 진입 상태·기기 권장·전체화면 단위 테스트 8개 추가
- 전체 59개 테스트 파일의 190개 테스트 통과
- ESLint, TypeScript, GitHub Pages·itch.io 프로덕션 빌드 검증
- `1280×720`, `1366×768`, `1920×1080`에서 캔버스 1.6 비율과 화면 내 맞춤 확인
- `800×600`, `375×667`에서 PC 권장 안내와 비차단 반응형 레이아웃 확인
- 실제 첫 클릭 후 진입 오버레이 제거, 게임 캔버스와 전체화면 제어 노출 확인
- 브라우저 콘솔 경고·오류 0건

## 트러블슈팅

- 전체화면 완료를 기다린 뒤 오디오를 재개하면 브라우저가 첫 클릭의 사용자 활성화 권한을
  잃을 수 있었다. 두 요청을 같은 이벤트 처리 안에서 즉시 시작하고 결과를 함께 기다리도록
  변경했다.
- 화면 크기를 연속 변경하는 QA에서는 Phaser의 비율 재계산이 비동기로 반영됐다. 각 리사이즈
  완료 후 실제 뷰포트와 캔버스 경계 사각형을 다시 측정해 왜곡 여부를 판정했다.

## 포트폴리오 포인트

웹게임의 첫인상을 단순 장식 화면이 아니라 실제 에셋 로더, 브라우저 권한, Fullscreen API와
연결했다. 실패·미지원 환경에서도 게임을 막지 않는 점진적 향상을 적용하고 여러 화면 크기의
수치 기반 QA 결과를 함께 기록했다.
